## 已确认的行为

1. 识别只看相册的完整相对目录（含上级文件夹），由外部 AI 解析；不看照片、不读照片元数据、不做人脸识别。
2. 作者是出品方 / 工作室 / 品牌，不是摄影师，也不是转载来源；模特是出镜的人。
3. 结果只作为识别建议，用户确认后才保存；不自动写入。
4. 只为空着的项给建议：没填作者才建议作者，一位模特都没有才建议模特；已填的不提示、不覆盖。
5. 识别服务支持 Claude、OpenAI、Gemini、Grok，以及其他兼容 OpenAI 格式的服务；同一时间只配置一个。
6. 发给识别服务的只有文字：要识别的相册路径、当前作者与模特名单、已填好的相册作为示例。不需要单独维护别名。
7. 只在整理页点「识别未填写的相册」时调用；上传、扫描不自动调用。
8. 可以建议名单里还没有的名字，单独标「新名字」；名单里已有的人用名单里的写法；没把握就不给。
9. 识别服务在设置页配置并保存在 `bijin.db`，不写 `.env`；AGENTS.md 不改，在 DECISIONS.md 记录调用外部服务的例外。
10. Claude 走原生接口（官方 Go SDK），OpenAI / Gemini / Grok / 其他兼容服务共用 OpenAI 格式（手写请求，不加依赖）；都不发送 `temperature`。服务器逐条检查回答，不合格的丢弃。
11. 设置页「识别服务」卡片：服务、接口地址（只有其他兼容服务需要填）、API Key（只写不读）、模型名（必填）、推理强度；测试（不保存）、保存、删除；保存后立即生效。
12. 推理强度：默认（不发送）/ 低 / 中 / 高，初始为默认。Claude 对应 `output_config.effort`，其余对应 `reasoning_effort`。
13. 整理页每个空位显示虚线框「建议」，带 ✓ 接受、✕ 忽略；新名字另有标记；「接受全部建议（N 本）」只作用于当前列表；接受走现有整理保存流程。
14. 建议只留在当前页面，刷新或离开即丢弃，不入库。
15. 每次最多识别当前列表中 100 本有空项的相册，浏览器每 20 本一批顺序发送，每批服务器最多等 50 秒；显示进度，每批完成即显示建议，单批失败不影响其他批；离开页面即停止。
16. 完成后显示「识别 N 本，给出 M 条建议，跳过 K 条」；失败显示原因，相册资料不变；不显示费用。

## 设计

### 识别服务配置

- SQLite 新表 `recognizer`，只有一行：服务、接口地址、API Key、模型名、推理强度。
- 服务取值 `claude` / `openai` / `gemini` / `grok` / `custom`。前四个的地址固定：Claude 用 SDK 默认地址；OpenAI `https://api.openai.com/v1`；Gemini `https://generativelanguage.googleapis.com/v1beta/openai`；Grok `https://api.x.ai/v1`。`custom` 填 http(s) 地址，请求发到 `<地址>/chat/completions`。
- 保存时 Key 留空表示沿用；换了服务必须重新填写 Key。接口从不返回 Key。
- 测试：用表单当前内容（Key 留空且服务未变时用已保存的 Key）发一次极小的真实请求，要求按同一 JSON 格式回答，不保存。

### 一次识别（服务器）

- `POST /api/recognize` 接收最多 20 个相册标识。服务器读取当前相册、名单与关联，跳过不存在、已填满或是根目录的相册。
- 请求内容：说明作者 / 模特的含义和规则、名单（作者、模特分开）、已填相册示例（最多 300 本）、待识别相册及各自缺哪一项。要求输出 `{"albums":[{"album","author","models"}]}`。
- Claude：Messages API，`output_config.format` 约束 JSON；推理强度非默认时设置 `output_config.effort`；`max_tokens` 16000；`stop_reason` 为 `refusal` 或 `max_tokens` 时按失败处理。
- OpenAI 格式：`response_format` 使用 JSON Schema；服务返回 400 且报错提到 `response_format` / `json_schema` 时，去掉该字段重试一次（提示词仍要求只输出 JSON）。推理强度非默认时发送 `reasoning_effort`。不发 `temperature`、最大输出长度。
- 整批期限 50 秒（在 OpenResty 默认 60 秒之内）。
- 逐条检查：相册必须在本批里且对应项仍为空；名字按现有规则清理（1–40 字、无控制字符），模特去重、最多 10 位；与名单同角色、按现有身份规则（只忽略英文大小写）相同时改用名单写法，否则标新名字。不合格的条目计入跳过数。
- 失败映射：Key 无效 / 无权限、找不到模型或地址、限流或额度不足、服务暂时不可用、超时、回答格式不对，返回中文原因（附服务原始错误摘要，最多 200 字）。日志记录服务、模型、状态、耗时和相册数，不记录 Key 与提示词。

### 整理页

- 读取 `GET /api/recognizer` 判断是否已配置；未配置时按钮不可点，并给出去设置页的链接。
- 目标：当前筛选列表中作者或模特为空、且不是根目录的相册，按显示顺序取前 100 本；浏览器每 20 本一批顺序请求。
- 建议按相册保存在页面内存；只在对应项仍为空时显示。接受时再次确认该项为空，经现有整理保存 module 提交（相同作者与模特组合合并成一次批量保存）。
