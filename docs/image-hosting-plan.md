# 原图分享设计

2026-10-13 11:50:27 CST。基线为 netcup 与 GitHub `master` 的 `2c55d26`。Q1–Q13 与最终理解确认 Q14 已由用户批准，包含项目说明的原图分享例外；2026-10-13 14:50:09 CST 已完成开发、验收、仓库发布和生产部署，并按用户要求清理部署备份、测试数据与旧镜像。

## 使用流程

1. 登录后，沿用现有上传页添加图片或打开已有照片。
2. 在大图界面点击「复制分享链接」，该原图开启分享，剪贴板得到完整图片地址。地址使用 `https://csb.jgbman.cc`，持有者无需登录即可直接查看原图，也能在其他网站引用。
3. 分享期间重复复制得到同一个地址。首版只复制图片地址。
4. 在大图界面点击「停止分享」，服务器立即拒绝旧链接的新访问。再次开启分享生成新地址，旧地址不会恢复。
5. 在现有图库开启「只看已分享」，找到当前分享的图片，再打开大图管理。

只有主动复制分享链接的原图获得分享许可，已有与新上传原图均不自动分享。分享不自动过期。同路径替换、移动或删除原图也使旧分享失效；替换后的图片需主动重新分享。

## 公开范围

- 分享链接返回选定原图的文件字节，不裁剪、不压缩，也不经过分享页面。
- 沿用当前图库支持的 JPEG、PNG、WebP 和 GIF；分享读取核对实际图片格式与响应类型，不仅相信文件扩展名。GIF 原图保持动画。
- 相册页面、图库列表、缩略图与普通 `/original/{id}` 入口继续要求登录；分享管理与已分享筛选也只在登录后使用。
- 随机壁纸、壁纸成品与登录页背景保持现有行为；即使未分享原图，其壁纸仍可能被现有公开接口选中。
- 已经下载或被第三方保存的图片无法收回；停止分享保证服务器拒绝之后的新访问。

## 拟实现的架构

继续使用现有 Go、Next.js 静态前端、SQLite、单容器与单进程。本地目录和现有 S3 存储都支持分享；新图沿用现有上传与照片处理流程。

- SQLite 保存一次分享的身份、对应照片与来源、原图版本及内容依据。每张原图同一时间最多一个有效分享身份，重启与登录状态变化不改变它。所有照片初始化空许可的修改代次记录；删除也保留并递增该代次，编号复用不会接纳旧操作。
- 新增独立的公开分享图片入口 `/i/<随机分享身份>.<图片扩展名>`。地址不使用可枚举的照片整数 id，不暴露原文件名或存储路径。
- 公开请求先验证分享许可、来源与原图内容，再通过现有来源读取能力由 bijin 返回图片。分享路径不签发对象存储直链，避免关闭后仍能通过已签发地址访问。
- 新增仅登录后可用的查看、开启及停止分享接口；写操作沿用同源门禁。开启操作核对大图中当时选择的版本，防止旧界面无意中分享替换后的图片；重复和并发复制复用同一次分享。
- 前端大图展示分享状态及复制、停止操作；复制失败时显示可手动复制的地址，不伪报复制成功。写操作失败保留真实状态并支持重新核对。
- 图库的已分享筛选由服务端执行，与全库及相册分页一致；分享状态变化使对应查询结果失效。

选择应用转发而非现有 S3 直连，是因为用户要求停止分享立即拒绝新访问。现有 S3 签名有效 24 小时，并具有独立缓存，不会在相册停止分享时撤销。分享传输会占用 netcup 流量。

公开图片响应需要适合直接显示与外站引用，支持 GET、HEAD 和现有图片读取所需的 Range。分享响应不提供可跳过权限检查的长期缓存；无效、停止、被删除或被替换的分享统一不返回原图。临时存储故障按故障处理，不擅自结束分享许可。

## 必须解决的现有实现限制

- `photos.id` 可能在删除后被复用；不能把分享许可只绑定到这个整数，避免旧链接指向后来新增的照片。
- 现有 `/original/{id}` 忽略 `?v=`，按当前路径取图；不能去掉它的登录门禁作为新图床入口。
- 现有原图读取不会实时核对来源版本；通知或扫描前，同名替换可能仍沿用旧索引。因此分享读取不能仅相信索引中的版本字段。
- 本地版本仅使用大小和修改时间，保留大小与修改时间的换图不能靠这些元数据识别。需要以实际原图内容验证分享对象，且不得在核对之前发送替换后的图片；并发原位修改也纳入验证。
- S3 需要核对权威来源状态并按条件读取，防止核对之后对象被覆盖。现有数据库不单独保存 ETag，不能无条件从版本字符串推断它。
- 原图改变、移动或删除后，旧分享身份不能在照片 id 复用、原图恢复或重新开启分享时恢复。
- 现有分页排序缓存只有快照、seed 和相册维度；分享筛选必须加入筛选模式和有效分享集合的变化，并在最终数据库读取时再次核对许可。前端切换筛选也必须重置已加载图片、seed 与游标，不能只改显示条件。
