# 整理页布局与按相册识别设计

2026-10-17 16:11:17 CST。基线为本地仓库的 `e496f6b`。本轮 Q1–Q17 已由用户逐项确认（全部采用推荐方案）。2026-10-17 17:00:27 CST 已实现并在 netcup 隔离环境验收（O01–O15 通过，见 `TEST_REPORT.md`）；尚未提交、推送与部署。

## 现状事实（2026-10-17 读代码核对）

- 整理页从上到下：筛选行（相册名 / 填写情况 / 作者 / 模特）→「全选当前列表」行（含「共 N 本」「清除筛选」）→「识别未填写的相册」按钮与进度 → 批量设置面板（有勾选时出现）→ 表头「相册 / 作者 / 模特」（纯文字）→ 相册列表。
- 窗口窄于 1100 像素时表头隐藏，每本相册折成两到三行。
- 批量面板出现在表头上方，点全选会把表头往下推。
- 改筛选不清空勾选：被筛掉、看不见的相册仍算在「已选 N 本」里。相册页「管理分享」改筛选时会清空。
- 整理页的相册默认按相册名排（服务器顺序），没有排序功能；相册页已有排序（名称 / 作者 / 模特 / 添加日期），存在 `localStorage` 的 `juens-album-sort`。

## 已确认的行为

1. 删掉单独的「全选当前列表」行。全选放进表头第一列，只有勾选框（全没选 / 部分 / 全选三态，读屏名称仍为「全选当前列表」），只管当前列表；「共 57 本 / 显示 12 / 57 本」放在表头「相册」后；「清除筛选」放在筛选行末尾，有筛选时才出现；「列表 / 网格」切换放在「整理相册」卡片标题右侧。
2. 点表头「相册」「作者」「模特」排序：第一次正序，再点倒序，标题旁箭头标出当前顺序；没填的始终排最后，规则与相册页相同（模特按第一位）；默认相册名正序；不加添加日期。
3. 填写后不立即重排：直到再点表头、改筛选或刷新页面才重新排序。
4. 排序记在这台设备，和相册页各记各的。
5. 网格视图：卡片和列表行功能相同（可改作者和模特、显示识别建议、勾选、识别），只是封面更大。默认列表视图，切换后这台设备记住。
6. 有勾选时：点已勾相册的识别图标 → 识别全部已勾选的相册；点没勾相册的识别图标 → 只识别这一本，不弹窗，不改勾选。
7. 作者和模特都已填写的相册、根目录相册，识别图标变灰，提示「作者和模特都已填写」；识别仍只补空项、不覆盖已填项；只填了一项的照常可点，只建议空着的那项。
8. 删掉「识别未填写的相册」按钮。一次识别多本 = 用「填写情况」等筛选 → 表头全选 → 点任一已勾相册的识别图标。进度、汇总、失败原因和「接受全部建议（N 本）」放在筛选行下面的一条提示行里，有内容才显示。
9. 弹窗：标题「识别所选的 12 本相册？」；正文「其中 9 本有空着的作者或模特，会发给识别服务；3 本已填满，跳过。」，超过 100 本时加「每次最多 100 本，按当前顺序识别前 100 本」；按钮「开始识别」「取消」。开始后弹窗关闭、勾选保留，正在识别的相册图标转圈，进度在提示行；识别期间其他识别图标不可点，同一时间只做一次识别。只勾了一本时直接识别、不弹窗。
10. 没配置识别服务时不显示识别列；提示行写「还没有配置识别服务，去设置页配置」并带链接。
11. 批量设置改为屏幕底部的浮动栏：「已选 N 本 ｜ 作者 ｜ 模特 ｜ 应用到所选相册 ｜ 取消选择」，滚到哪都能用，没有勾选时消失。
12. 表头往下滚时固定在顶部。
13. 改任何筛选条件（搜索框打字、填写情况、作者、模特、清除筛选）都清空勾选；改排序不清空。
14. 窄于 1100 像素和网格视图里，表头变成一条精简栏：「☐ 共 57 本 ｜ 排序：相册↑ 作者 模特」，三个小按钮用法与宽屏表头相同，同样固定在顶部。窄屏列表里识别图标放在相册名同一行的右上角。
15. 网格与相册页一致：宽屏每行 4 张、中等 3 张、手机 2 张；封面电脑上裁成 4:3、手机上 3:4。封面下依次是相册名和张数、作者下拉、模特下拉，建议显示在对应下拉下面；勾选框在封面左上角，识别图标在右上角，样式同相册页「管理分享」的勾选方块。
16. 手机上的底部栏分两行：第一行作者、模特两个下拉并排；第二行「已选 N 本」「应用到所选相册」「取消选择」。列表末尾留出底部栏的高度；「已设置 N 本相册」「先选择作者或模特」等提示显示在栏里。
17. 沿用术语表叫法，界面不出现「AI」：表头图标提示「识别建议」；单本图标提示「识别这本相册」；勾选多本时已勾相册的图标提示「识别所选的 12 本相册」。

本方案替代 `docs/album-recognition-plan.md` 已确认行为的第 7 条（只在点「识别未填写的相册」时调用）、第 13 条中「接受全部建议」的位置，以及第 15 条的识别范围（由「当前列表中有空项的前 100 本」改为「单本或所选相册中有空项的前 100 本」）。其余识别规则不变。

## 设计

- 只改前端：`frontend/components/organize-panel.tsx`、`frontend/lib/albums.ts`、`frontend/lib/recognition.ts`、`frontend/app/globals.css`。不改 Go 接口，不加依赖；弹窗用已有的 `components/ui/dialog.tsx`。
- 排序：复用 `sortAlbums` 的名称 / 作者 / 模特规则；整理页偏好另存 `juens-organize-sort`，视图存 `juens-organize-view`，读写失败时用默认值。页面保存一份按顺序排列的相册编号，在读取完成、点排序、改筛选时重新计算；填写只更新内容，不改顺序。
- 勾选：所有筛选变化的入口统一清空勾选；全选只覆盖当前列表。
- 识别：`recognition.run` 仍接收相册编号，由页面传入单本或「所选相册中有空项、非根目录、按当前顺序」的编号；module 额外给出本次还没完成的相册，用于行内转圈。每次最多 100 本、每 20 本一批、单批失败不影响其他批、离开即停止，均不变。
- 布局：宽屏列表表头与行共用同一组列（勾选 / 封面 / 相册 / 作者 / 模特 / 识别），表头 `position: sticky` 固定在顶部；窄屏与网格换成精简栏。底部批量栏 `position: sticky` 固定在底部。

## 实现中的调整（2026-10-17 17:00:27 CST）

截图与浏览器测试发现以下问题，按方案原意调整：

1. 宽屏表头的「共 57 本」放在「相册」这一列的右端，不紧贴「相册」二字：三个排序按钮在 DOM 里合成一组，窄屏精简栏才能整组换行，计数因此不能和「相册」按钮放进同一个容器。
2. 宽屏列表的相册列至少 10rem，作者、模特列先让出宽度：加了识别列后，1100 像素左右且侧栏展开时相册列只剩约 30 像素。
3. 手机（窄于 720 像素）的精简栏不显示「排序」二字，排序按钮收紧，375 像素宽时一行放下；320 像素时排序按钮整组换到第二行。手机列表的勾选列收窄为 2rem（点击范围仍是 44 像素），否则 320 像素时相册名被挤成一个字一行。
4. 批量栏在「应用」后已没有勾选时只显示结果提示，并带 ✕ 关闭；手机上「取消选择」只显示 ✕ 图标（读屏名称仍为「取消选择」），否则 375 像素时被挤到第三行。
